# Protocol stabilization roadmap — status 2026-11-15

| Gate | Requirement | Status | Evidence |
|---|---|---|---|
| C0 | Workspace builds; Rust tests pass on Linux and Windows | **PASS** | full workspace suite, clippy `-D warnings` and the source gate run on Linux and Windows for every release build (1.0.1, 1.0.2, 1.0.3); the release gate counts for each published build are recorded in the Project repository (`docs/reports/`, `docs/compatibility/`) |
| C1 | Authoritative request/op matrix | **PASS** | `v1/method-matrix.json` (31 client methods, 9 host-originated, 81 ops): param schemas and ops generated from the Rust serde types; the client-method list is hand-maintained and `--check` fails if it diverges from the dispatch `match` arms; host-originated messages are hand-listed and not cross-checked |
| C2 | Typed schemas verified against Rust decoders | **PASS** | generated schemas + runtime golden (unknown/missing/wrong-type cases); unit-variant exception documented |
| C3 | Independent clients open a window, submit a form, quit | **PASS** | `nativehtmlkit-cli` (Rust), `nativehtmlkit-python` and `nativehtmlkit-powershell` (PowerShell 7 and Windows PowerShell 5.1) native GUI suites from packaged artifacts on KDE Plasma Wayland and an interactive Windows desktop |
| C4 | Malformed framing, duplicate keys, invalid IDs, unexpected params characterized | **PASS** | golden `envelope.*`, `security.*` cases; the golden also locks boolean result values, array lengths, `bitmap.present`, `app.force_quit` and (1.0.3, 342 cases) `document.load` path/asset_root results and `host.diagnostics.dropped_notifications`; identical on Linux and Windows |
| C5 | Interop with independent v1 clients | **PASS** | the unmodified UI4ME 1.0.1 Python SDK (Linux headless, host 1.0.1) and three independently implemented clients (Rust CLI, Python stdlib, C#/PowerShell) qualified against the same host binaries |
| C6 | Native GUI qualification: input, focus, resize, DPI, accessibility, IME | **PASS** with the limits listed | pointer/keyboard/focus/resize/scroll/close, native file dialogs and clipboard on both OS (client GUI suites). Native journeys on KDE Plasma Wayland and interactive Windows: IME composition (fcitx5 pinyin; Microsoft Japanese IME), display scaling 100-200 % incl. live changes, screen readers (Orca + AT-SPI; NVDA + UI Automation), multi-monitor incl. mixed scale on Linux, session lock / RDP reconnect / VM pause, 30-minute endurance. One defect found there (NHK-CROSS-0009, drop-down focus reported on an option) is fixed in 1.0.3 and verified with Orca and NVDA on the released hosts. **Open defect in 1.0.3:** NHK-CROSS-0010 (Linux, Orca: a value change of a collapsed drop-down by arrow key is not announced; the value does change). On the released 1.0.3 hosts the journeys were re-run for IME, scaling, screen readers and multi-monitor on both OS; the 30-minute endurance and lock/pause journeys were completed on 1.0.2 and only partially repeated on 1.0.3. **Not qualified:** mixed per-monitor scale on Windows, a real S3 suspend/resume, file drag-and-drop from other applications |
| C7 | Artifact provenance, pinned host, hashes, local packaging | **PASS** | `scripts/release-local.py`: the host embeds its source identity (commit, tree, dirty flag) and staging refuses a binary not built from the staged checkout or one containing local paths; deterministic archive with full third-party licence texts, verified from a clean extraction |
| C8 | Public v1 stability declaration | **PASS** | declared with host 1.0.3 (2026-11-16) on the evidence of C0-C7 |

Do not mark the public contract stable solely because JSON Schemas validate or headless tests pass.
v1 was declared stable only after the C6 native evidence above existed; from then on, any gate
regression in a 1.x host is a release blocker, not a reason to reopen the contract.
